사용자 문제와 검증 방향

반복 입력에서 수치가 잘리거나, 복약 기록의 의미가 바뀌거나, 백업에서 설정이 빠지면 사용자는 기록을 신뢰하기 어렵습니다. 기능이 있다는 사실보다 실제 사용 조건에서 값과 과거 기록이 유지되는지를 확인했습니다.

  • 입력값과 표시값의 일치
  • 정기 복약과 필요 시 복약(PRN)의 구분
  • 복원 후 데이터와 설정의 보존

수행 역할

  • 직접 수행: 실제 사용, 문제 발견, 요구사항 선택·우선순위 결정, 실기기 확인과 최종 판단
  • AI 협업: 요구사항 구체화, 시나리오·구현 방향 정리, Codex 작업 지시와 결과 검수
  • AI·Codex 중심: 코드 구현, 테스트 코드 작성, 반복 자동 검증과 기술 수정

사례 01 · V3.4.0 · 2026-08-30 기록

검사 수치가 끝까지 보이는 입력 화면

사용자 문제 · 발견 조건
좁은 검사 입력란에서 소수 값의 전체 문자열을 확인하기 어려웠습니다. 같은 검사 항목이 서로 다른 이름으로 저장되어 통계에서 빠지는 문제도 확인했습니다.
요구사항 · 우선순위
저장 전에 입력값을 읽을 수 있어야 하며, 이미 알려진 이름 차이는 통계에 포함해야 한다고 정리했습니다. 입력 안전성과 기존 기록 보존을 우선하고, 유사한 사용자 항목까지 임의 통합하지 않도록 범위를 제한했습니다.
AI 구현 · 본인 검수
입력란 너비와 표시 방식, 명시적인 이름 대응 규칙은 AI/Codex가 구현했습니다. 본인은 실제 입력 흐름과 화면을 검수했으며, 원본 QA 기록에는 Galaxy SM-S918N에서 소수·정수 입력 표시와 통계 확인 결과가 남아 있습니다.
개선 후 반복 확인
원본 테스트와 QA 문서에서 소수 문자열 표시, 저장값 유지, 기존 통계 반영을 확인했습니다. 같은 날짜의 기존 행은 병합·덮어쓰기·삭제하지 않는 조건도 회귀 범위에 포함했습니다.

범위: 직접 입력과 알려진 검사명 대응. 단위 변환이나 임의의 유사 이름 추정은 포함하지 않습니다.

사례 02 · V3.5.0 · 2026-08-30 기록

필요 시 복약을 실제 기록으로 구분

사용자 문제 · 발견 조건
필요할 때 복용하는 약(PRN)은 등록되어 있다는 이유만으로 미복용이나 복용 권장처럼 보이면 오해를 만들 수 있습니다. 같은 날 여러 번 복용한 기록과 과거 기록 수정도 구분할 필요가 있었습니다.
요구사항 · 우선순위
Home에는 오늘 실제 저장된 PRN 기록만 표시하고, 첫 복용과 추가 복용을 구분하도록 정리했습니다. 과거 용량을 현재 값으로 추정해 채우지 않고 기록의 의미를 유지하는 것을 우선했습니다.
AI 구현 · 본인 검수
Home 표시 조건과 복용·추가 복용, 과거 기록 편집은 AI/Codex가 구현했습니다. 본인은 사용자 관점에서 표시와 흐름을 검수했습니다. 원본 실기기 기록은 Home의 당일 PRN 표시와 과거 기록 입력·편집 화면 진입 확인을 포함합니다.
개선 후 반복 확인
자동 회귀 범위에는 기록이 없는 날의 미표시, 같은 날 추가 기록의 독립 저장, 편집 시 기록 식별자와 관련 증상 관계 보존이 포함됩니다.

실기기 확인은 기존 데이터를 보호한 화면 smoke 범위입니다. 과거 기록의 파괴적 저장을 모두 실기기에서 검증했다고 표현하지 않습니다.

사례 03 · V3.6.0 · 2026-08-31 기록

검사 기록뿐 아니라 설정까지 복원

사용자 문제 · 발견 조건
기존 백업에는 검사 결과가 포함되지만 검사 항목 설정은 빠져 있었습니다. 결과값이 남아도 선택한 관리 유형·표시 항목·사용자 정의 항목이 복원되지 않으면 이전 입력 환경을 잃을 수 있었습니다.
요구사항 · 우선순위
설정도 백업 계약에 포함하고, 이전 백업을 계속 읽을 수 있어야 한다고 정리했습니다. 복원 실패 시 기존 DB와 설정을 보존하는 조건을 우선했습니다.
AI 구현 · 본인 검수
백업 형식 확장과 복원·롤백 코드는 AI/Codex가 구현했습니다. 본인은 복원 범위와 데이터 보존을 검수했습니다. 원본 기록에는 Galaxy SM-S918N에서 설정만 변경한 뒤 백업으로 되돌리고 재실행 후 유지 여부를 확인한 결과가 있습니다.
개선 후 반복 확인
자동 회귀는 구형 백업 호환, 사용자 정의 단위의 빈 값 유지, 잘못된 설정 거부, 실패 시 DB·설정 롤백을 포함했습니다. 실기기에서는 기존 기록이 남아 있는지 함께 확인했습니다.

실기기 근거는 설정 복원과 기존 데이터 존재 확인 범위입니다. 모든 개인 데이터를 삭제한 뒤 전체 복원하는 실험과는 구분합니다.

검증 범위와 결과 판단

사례자동 회귀 · AI/Codex 중심원본 실기기 QA 기록 범위
검사 입력전체 문자열·저장값·명시적 이름 대응·기존 행 보존소수·정수 입력 표시, 알려진 이름의 통계 반영
PRN 기록미기록일 미표시·추가 기록·편집 시 관계 보존Home 당일 표시, 과거 기록 편집 화면 smoke
백업/복원설정 왕복·구형 호환·잘못된 파일 거부·롤백설정 복원·재실행 유지·기존 데이터 존재

기능별 반복 검증과 Android 실기기 확인을 구분해 기록했습니다. 자동 테스트 수치를 본인의 코딩 실적으로 제시하지 않습니다.

QA 판단을 위한 기술 배경

Android / Flutter와 로컬 SQLite 기반입니다. 저장값, 화면 표시, 과거 기록과 백업 설정의 관계를 검증 대상으로 삼았습니다. 구현 구조보다 변경이 사용자 기록에 미치는 영향을 중심으로 범위를 정했습니다.

검증 경계와 배운 점

사례의 기준은 V3.4~V3.6 원본 QA·변경 기록입니다. 검사 사진 입력과 혈압·체중 사진 인식은 이 세 사례의 검증 범위에 포함하지 않았습니다. iOS 출시나 의료적 판단 기능을 제시하지 않습니다.

실사용 문제를 요구사항으로 바꾸고, 개선된 기능과 기존 동작을 함께 확인하는 경험을 쌓았습니다. 실행 환경과 데이터 보호로 확인하지 못한 범위도 결과에 남기는 것을 중요하게 생각합니다.
